### F. Fonctionnalités de résilience ajoutées à l'adaptateur

L'adaptateur `.ai/ux-agent/opencode-auto.cjs` intègre désormais les mécanismes suivants pour maximiser la disponibilité du tool calling natif :

| Fonctionnalité | Description |
|----------------|-------------|
| **Pré-probe cloud** | Vérifie si le fournisseur cloud est joignable avant de lancer OpenCode. Échec = avertissement seulement, ne bloque pas (OpenCode gère la connexion réelle). |
| **Retry avec backoff exponentiel** | Jusqu'à 3 tentatives (2s, 4s, 8s) en cas d'échec transitoire d'OpenCode. |
| **Circuit breaker** | Après 3 échecs consécutifs, le cloud est écarté pendant 60 secondes. L'adaptateur bascule alors sur le modèle local avec un avertissement explicite (tool_calls indisponibles). |
| **Chaîne de fallback** | Tente les modèles cloud configurés par ordre de priorité (NVIDIA → OpenRouter) jusqu'à ce qu'un fonctionne. |
| **Dégradation gracieuse** | Si aucun cloud n'est disponible et que le modèle local manque de tool_calls, l'adaptateur exécute quand même le modèle local et avertit explicitement l'utilisateur que les tool_calls ne fonctionneront pas. |
| **Mode local-only par défaut** | Quand aucune clé cloud n'est configurée, le comportement est inchangé (local Ollama uniquement). |
| **Flag `--cloud`** | Force le mode cloud explicitement, même si le routeur local sélectionnerait un modèle avec tool_calls. |

### Limites de la résilience

| Limite | Explication |
|--------|-------------|
| Dépendance clé API | Le cloud nécessite `NVIDIA_API_KEY` ou `OPENROUTER_API_KEY` déjà configurée dans l'environnement. |
| Aucun SLA | Le fournisseur cloud NVIDIA n'a pas de SLA garanti dans cette configuration. |
| OpenRouter gratuit instable | Timeouté lors des tests ; non fiable pour production 24/7. |
| Circuit breaker temporaire | 60 secondes de blocage après 3 échecs, puis réessai automatique. |
