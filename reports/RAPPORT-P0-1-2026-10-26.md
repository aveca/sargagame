## 3. Correctif appliqué : Garde-fou anti-faux-succès

### Problème identifié
L'agent `lucid` peut déclarer une tâche comme réussie (`exit 0`) alors qu'aucun fichier n'a été réellement modifié. Le modèle génère du texte qui ressemble à un appel d'outil, mais aucune action n'est exécutée sur le système de fichiers.

### Correctif appliqué

**Fichier :** `scripts/autopilot/local-agent-executor.cjs` (dans le miroir `sargagame-iso`)

**Emplacement :** Lignes 404-416 (après l'exécution de l'agent)

```javascript
// 4. Verifier que l'agent a REELLEMENT produit une modification.
//    Un code de sortie 0 ne prouve rien : le modele peut repondre en texte,
//    appeler 'read' puis s'arreter. On distingue succes du processus et
//    succes de la tache. Une tache d'analyse (sans fichiers en scope) peut
//    legivement ne rien modifier ; une tache d'edition doit produire un diff.
const scopeFiles = (task.files && task.files.length) ? task.files
  : ((task.scope && task.scope.files) || []);
const editRequired = Array.isArray(scopeFiles) && scopeFiles.length > 0;
const producedDiff = gitops.diffStats(wt);
if (editRequired && producedDiff.files.length === 0) {
  throw new Error(`Agent produced no modification: exit 0 but empty git diff. Edit was required on: ${scopeFiles.join(', ')}. Model: ${agentResult.model || 'unknown'}.`);
}
log(`[diff-guard] editRequired=${editRequired} fichiersModifies=${producedDiff.files.length}`);

const diff = producedDiff;
```

### Ce que fait ce garde-fou :
1. Détermine si la tâche attend une modification de fichier (`editRequired`)
2. Vérifie si `git diff` montre des changements réels dans le worktree
3. Si une modification est attendue mais qu'aucun fichier n'a été modifié, lève une erreur explicite
4. Empêche ainsi le faux succès : "Task completed successfully" alors que rien n'a été fait

### Pourquoi ce garde-fou est nécessaire
Avant ce correctif, un agent pouvait :
1. Répondre "J'ai écrit le fichier" (texte dans `content`)
2. Terminer avec `exit 0`
3. Le harnais considère la tâche comme réussie
4. Mais aucun fichier n'a été créé ou modifié

Avec le garde-fou, l'agent est bloqué à l'étape de vérification si aucune modification n'a été produite, forçant soit une nouvelle tentative, soit un rapport d'échec honnête.
